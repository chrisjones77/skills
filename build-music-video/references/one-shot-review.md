# One-shot production for a review cut

Use this method when the user asks for a quick rendition, wants planning done up
front, or will be unavailable until a playable review cut is ready. Here,
“one-shot” means one planned production pass through delivery, with bounded defect
repairs. It does not promise that every generated image succeeds on its first try.
It does not authorize publication or waive a required source or permission decision.

## Plan before generating

Lock the selected recording by stable identity, source-file hash and measured
duration. Reconcile a reported duration with the actual file before choosing cuts;
keep the full selected recording unless an audio edit was requested. Resolve the
lyric source and the basis for treating it as sung text, including any explicit
owner clarification. Preserve the raw source and fallible transcript separately.

Resolve factual visual references now. If a linked gallery is broken, inspect
available authorized local copies or connected storage before substituting generic
scenery. Save a compact reference index with provenance and the invariants that
matter: geography, building/object identity, relative positions and current versus
proposed states. A style reference supplies style; it does not automatically supply
the location, people or events. If an essential reference remains unavailable,
complete independent planning and name the missing decision rather than inventing
an accurate-looking site. An unrelated broken website is a separate repair scope.

Make a section map and a lyric-payoff map, then an editable shot table covering the
whole recording. Interpret “gems” or similar shorthand as standout lines when the
creative context supports that meaning. Identify what each line needs the viewer
to see and whether a still state, ordered sequence or animation supplies it.

Choose an approximate pace from the request. About ten seconds per scenic shot can
be a starting point when requested; it is not a universal rhythm or minimum hold.
Reserve shorter cuts for dense payoffs and longer holds for breathing space. Budget
unique illustrations separately from edit segments, plan reprises deliberately,
and include the final instrumental tail. Record output geometry, cast/props,
caption safe areas, estimated timing, delivery size and the review/publication
boundary in the same plan. Use the existing project record rather than a parallel
tracker. Keep this plan editable; it is not an approved timing baseline by itself.

## Produce within the plan

Generate individual production images at the destination aspect ratio with a
shared continuity specification. Use bounded tool concurrency appropriate to the
available resources. A review contact sheet may summarize them, but its crops are
not production footage. Keep exact typography separate from generated lettering
when that makes the words easier to preserve and review.

Prepare an illustrated treatment, then continue through assembly and checks within
the user's existing authorization. Do not add a storyboard approval stop when the
user requested a completed review cut without intermediate gates. Continue to honor
any approval they did request and any unresolved authority needed for an action.

Inspect candidates before assembly. Repair concrete defects such as an extra
character, wrong object state, misplaced building, changed roof colour or caption
covering its payoff. Make a narrow correction, preserve the preceding candidate,
and recheck the affected invariant plus nearby continuity. Do not turn this into an
open-ended search for alternative styles or shots. If a repair cannot resolve a
material defect within the planned effort, retain the checkpoint and identify what
is needed; do not label the defect accepted. Cosmetic alternatives can wait for the
user's review unless they affect the requested result.

Assemble the complete planned edit with the selected soundtrack. Keep raw ASR,
canonical wording, display captions and actual listening evidence distinct. A
transcript or successful decode does not establish a listening review. Sparse
phrase captions are preferable to invented word-level timing when evidence is weak.

## Validate the master and the phone copy

Apply the full structural checks from the main skill. Inspect actual exported
frames covering the opening, every unique scene, each critical payoff, caption safe
areas and ending. Source art or a contact sheet alone cannot establish that the
export is correct. Record unique source assets, timeline segments and meaningful
visual changes with a declared counting rule.

Choose a phone derivative using actual file size, legibility and the host's inline
limits rather than a fixed bitrate or resolution copied from a previous project.
Keep the higher-quality master. A smaller encode is a new artifact: independently
check its full decode, frame count, geometry and both stream durations, then inspect
representative phone frames including text-heavy payoffs and the ending. Smaller
file size and copied captions do not prove a readable or complete derivative.

When comparing audio, name the method and pair of artifacts. A source-file hash,
copied encoded audio packets and decoded PCM similarity support different claims.
Lossy encoding does not preserve the original MP3 bytes; a similarity score is not
listening acceptance. Do not claim identical pixels after a lossy resize/re-encode.

## Deliver and retain

Put the playable phone copy inline when supported, followed by the treatment,
master and portable rebuild kit. State actual runtime, moving-still versus character
animation, timing uncertainty, checks run and the remaining publication decision.
If inline playback is unavailable, use the host's supported preview or usable file
attachment; do not claim that a desktop-only local link is mobile playback evidence.

Treat the illustrated HTML treatment as a deliverable in its own right. Embed its
preview images or bundle relative assets, keep audio/video references usable within
the kit, and distinguish a self-contained treatment from one that needs sibling
media. Keep inputs relative to the edit manifest, record source hashes and export
receipts, and exclude credentials, caches and unrelated private material. Do not
copy a real project's private photographs or account paths into reusable examples.

When preservation or stand-down is requested, verify a retained copy's file/byte
manifest and give it a durable index outside disposable build output. Keep prior
manifests and kits unchanged; append preservation/release receipts separately.
Record the live version separately from creative drafts. Standing down further
creative work does not request rollback or deletion of a published version. Retain
source/output media and unresolved work ownership; cleanup is a separate decision.

For a later release, pass the selected export/hash and actual approval scope to the
project's operator. Establish the publication target and any CI-offline exception's
scope/expiry before release work; reuse still-applicable authorization without
inventing new gates, extending an exception to another release, treating offline CI
as passing, or changing account settings to bypass it. The review-cut request alone
is not release authorization.
