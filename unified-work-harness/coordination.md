# Attended work and handoff

Import `offerCoordination`, `inspectCoordination`, `respond`, `reoffer` and `handoff` from `coordination.mjs`. These functions return private records to the caller. The operator preserves the latest record, verifies each actual response and reconciles concurrent copies before accepting another action. Each action requires the current assignment digest. Person, team and agent labels record a declared recipient. For hybrid work name the accountable person and identify which part the tools performed in the evidence.

1. Prepare the intake fields in SKILL.md, a workspace record, a unique work ID and a primary purpose. Record the actual intake review using [the intake API](intake.md). Offer with `offerCoordination({intake, review, workspace, id, purpose})`. The review is bound to the offer and rechecked before acceptance and resume. Give the named recipient the actual outcome, authority, exclusions, effort and review criteria.
2. Obtain the actual reply. Pass it to `respond(record, action, {by, assignmentDigest, note, ...details})`. Use `accept`, `declined`, `deferred` or `withdrawn`. The assigner can record `timeout` with a caller-owned checkpoint. A disposition requires a checkpoint. Use `reoffer` for a changed outcome and fresh acceptance. The record retains each superseded intake and review alongside its corresponding assignment digest. Copying an old acceptance into a new record invalidates its digest.
3. Use `clarify` with concernId, question and named human route. An assigner or named human can `answer`; only the recipient can `reassess` that answer using its digest and decision clear or ambiguous. The assigner can `reroute` a pending human question. Keep the original statement, answer and decision attributable. Resolve dependent concerns before resuming.
4. Record an explicit `resume` with a checkpoint after acceptance. The recipient may `pause`. For a transfer, first pause work, resolve outstanding concerns, then use `handoff(record,{assignmentDigest,by,note,intake,review})`. The result contains the withdrawn predecessor and a new unaccepted offer for the named successor. The owner must select that result as the current record. Pending concerns cannot be cleared by this transfer.
5. Use `submit` with an evidence reference. Only the named reviewer records `rework`, `approve` and `close` with their evidence. Rework requires another explicit resume. See coordination.test.mjs for executable human, hybrid and agent examples. All attended scopes are distinct from provider-executable contracts.

For intake, ask the responsible person to reconcile equivalent effects phrased differently (for example “send report” and “no external contact”), validate their authority source, confirm actual reviewer capacity and record evidence externally before offering. A populated intake alone supports review, not dispatch. A deadline in intake is a planning date; a provider execution window is a separate accepted policy.

Attended scope v2 binds the declared workspace root, identity, revision and status digest. It does not inspect the actual workspace. To change any of these fields, the assigner uses `reoffer` on the intact record with the new `workspace`; the previous workspace stays in revision history and the new offer starts paused and unaccepted. Do not patch the record in place. Older attended v1 scopes lack this binding: retain them as history, stop dependent work and explicitly review, offer and accept a new bound record before continuing. Existing queue entries are not silently migrated.

Work events must follow the offer and their predecessors in time. Each submission consumes a distinct resume checkpoint. For a provider packet, call `hypervisor.resumeAssignment(packet, {by, assignmentDigest, note})` after acceptance or rework and use the returned packet. The attended `resume` action does this internally. The checkpoint records the assignment digest, work-event count and checkpoint position, so two successive actions can share a timestamp.

Older checkpoints without those fields can establish a first resume at acceptance. After additional work events or a pause or clarification, an unbound resume must be distinguishable by time from the transition that preceded it. Reconcile an ambiguous historical submission with the owner. For paused work awaiting a new resume, record the recipient’s actual response against the current assignment. Preserve the original record.

Packet inspection matches each clarification checkpoint to its request, answer, routing decision or worker reassessment in recorded order. A request keeps the writer paused until the worker clears the matching response and explicitly resumes. Older clarification checkpoints without an assignment digest and work-event count are checked against the concern history. When both fields are recorded, inspection also checks the assignment and its position in the work history.

When loading a handoff, inspection checks the successor’s first offer against the predecessor’s last assignment. The accountable assigner must have withdrawn the work with review pending. The new offer must follow that withdrawal, name a different recipient and preserve the work ID, purpose and workspace. A later reviewed revision can change the successor’s workspace.
