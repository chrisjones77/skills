# Reviewing a change to the unified work harness

From the repository root, run `node scripts/test_convergence.mjs suite`. The JSON report identifies the revision, package digest, Node and Git versions, observed filesystem case behaviour, and the named adverse cases and successful controls. The runner executes every package test and refuses missing, renamed or skipped required cases. Only the two opt-in model tests may skip. The [scenario table](../scripts/test_convergence.mjs) maps all 20 [public capabilities](../unified-work-harness/capabilities.md) to required evidence. For the seven methods, that evidence is availability, binding and the worked example; Christopher reviews the substantive advice and its suitability.

| Boundary | What a passing case observes |
|---|---|
| Scope and admission | For v1–v6, independently substitute every scalar in the accepted scope, check zero discovery, ledger and result effects, then complete an unmodified contract. v1 binds assignment bytes; v2 adds the draft and endpoint; v3 adds results; v4 adds single-attempt storage; v5 adds time; v6 adds the package profile and reviewed intake. Queued v5/v6 also preserve the original budget and jobs on a substitution. |
| Transport | Count actual requests at the accepted and forbidden listeners. Discovery, direct completions, both candidate protocols and the read worker see 301/302/303/307/308. The installed worker must perform a real read and send the token to the accepted endpoint. A streaming 200 succeeds. Relay credentials, method, path, closure and case-specific URL admission are checked. |
| Filesystem and ownership | Verify storage outside the checkout by physical identity. Exercise symlink and case aliases, temp replacement, protected names, hidden edits and Git filters. Linux and macOS must report different, expected case semantics on the test volume. |
| Lifecycle, budgets and recovery | Compare attended actions to an independent transition table. Force a contender to resume after the old lease has a new owner. Kill the real queue worker after reservation, claim, result persistence or ledger completion; inject a write failure separately. Verify provider calls, persisted state after restart, artifacts and charges. |
| Candidate integrity | Both protocols exercise token budgets, actual response bytes around the limit, broken streams, malformed replies, tool calls, forbidden edits and single-attempt replay. Recompute artifact hashes and refuse changed receipt fields and bytes. |
| Distribution and illustration | Install only the manifest files. Run the offline walkthrough. Compare all gallery transcripts to their manifests; verify selected and retained bytes and lineage. Chrome checks the six steps, keyboard navigation, full image and horizontal fit at 390 and 1280 pixels. Only a human can accept the actual illustration. |

**Other gates.** Run `node scripts/test_convergence.mjs worker` with the pinned OpenCode on PATH (CI checks the archive digest and version). The model is a synthetic loopback server. Run `python3 scripts/test_convergence_mutations.py` to reintroduce five historical faults in temporary copies. A mutant only counts as detected if its adverse case fails for the expected reason and its valid control passes. Run `python3 scripts/validate_storyboards.py` and `python3 scripts/test_storyboard_coverage.py`; the storyboard workflow also runs the browser check with Chrome and its pinned driver.

**Review decision.** Attach same-revision reports, platform results, installed-worker and mutation results to the PR. On provider-facing changes also exercise the opt-in live local-model tests with synthetic data. A newly found defect reopens its family and calls for a new scenario where coverage was missing. A pass on retry needs an explanation. Track faults first found after a green gate and the number of review/repair rounds. Green automation does not accept a method, authorize work, approve a candidate or merge a change.
