# Reviewing a change to the unified work harness

From the repository root, run `node scripts/test_convergence.mjs suite`. The JSON report identifies the revision, package digest, Node and Git versions, observed filesystem case behaviour, and the named adverse cases and successful controls. The runner executes every package test and refuses missing, renamed or skipped required cases. Only the two opt-in model tests may skip. The [scenario table](../scripts/test_convergence.mjs) maps all 20 [public capabilities](../unified-work-harness/capabilities.md) to required evidence. For the seven methods, that evidence is availability, binding and the worked example; Christopher reviews the substantive advice and its suitability.

| Boundary | What a passing case observes |
|---|---|
| Scope and admission | For v1–v6, independently substitute every scalar in the accepted scope, check zero discovery, ledger and result effects, then complete an unmodified contract. v1 binds assignment bytes; v2 adds the draft and endpoint; v3 adds results; v4 adds single-attempt storage; v5 adds time; v6 adds the package profile and reviewed intake. Queued v5/v6 also preserve the original budget and jobs when the envelope or packet workspace is substituted. Creation checks each bound workspace before opening SQLite. A queue copied inside the checkout must refuse dispatch before reservation or provider discovery. |
| Transport | Count actual requests at the accepted and forbidden listeners. Discovery, direct completions, both candidate protocols and the read worker see 301/302/303/307/308. The installed worker must perform a real read and send the token to the accepted endpoint. A streaming 200 succeeds. The installed worker also encounters checkout-defined MCP startup, unoffered instructions, a link outside the checkout and instructions beside a nested read. The observers check for a spawned process and inspect provider bodies for unoffered text. Relay credentials, method, path, closure and case-specific URL admission are checked. |
| Filesystem and ownership | Verify storage outside the checkout by physical identity. Exercise symlink and case aliases, temp replacement, protected names, hidden edits and Git filters. The installed-worker lane runs on Linux and macOS. On the insensitive volume, both Unicode alias fixtures must open the same file under the other spelling. The harness must reject the grants before provider discovery, while an exact Unicode directory grant permits the read. |
| Lifecycle, budgets and recovery | Compare attended actions to an independent transition table. Force a contender to resume after the old lease has a new owner. Kill the real queue worker after reservation, claim, result persistence or ledger completion; inject a write failure separately. Verify provider calls, persisted state after restart, artifacts and charges. The ledger cases check digest traversal, redirected finalization, malformed or aliased records, receipt-to-claim binding, and claim damage during candidate and v6 execution. |
| Candidate integrity | Both protocols exercise token budgets, actual response bytes around the limit, broken streams, malformed replies, tool calls, forbidden edits and single-attempt replay. Recompute artifact hashes and refuse changed receipt fields and bytes. |
| Worker outputs and edit evidence | A v6 result requires a valid event stream within both budgets. Direct proposal cases check source bytes and hashes at the directory budget, single-choice assistant completions on both adapters, and cancellation of an oversized loopback response before EOF. Synthetic Codex and Aider executables exercise launch arguments, rejected events, edit scope, and patch replay against the accepted Git revision. |
| Distribution and illustration | Install only the manifest files. Run the offline walkthrough. Compare all gallery transcripts to their manifests; verify selected and retained bytes and lineage. Chrome checks the six steps, keyboard navigation, full image and horizontal fit at 390 and 1280 pixels. Only a human can accept the actual illustration. |

The low-level Codex proposal adapter is exercised with a synthetic executable. Tests inspect the actual launch directory and arguments, turn ordering, reported tool use, stdout and stderr byte limits, timeout, and the contents of persisted diagnostics. A proposal requires an answer from the final completed turn. Tool events reject the transcript if observed. The host remains responsible for enforcing process and network isolation.

The low-level Aider tests use a synthetic editor to inspect its file arguments and byte ceilings. Acceptance cases distinguish an expected nonzero exit from a signal, timeout, or output overflow. Each passing edit check re-verifies the base revision and candidate diff before the next check runs. An unrelated untracked build product may remain in the disposable checkout. The receipt records hashes for complete output streams. Worker stdout and stderr are each limited to the assignment ceiling, and acceptance commands have a 5 MiB ceiling per stream.

The macOS suite also reports line, branch and function coverage of the seven top-level runtime modules on Node 22.23.4. Its job summary shows percentages; the `runtime-coverage-macos` artifact includes uncovered line ranges. This measurement excludes tests, synthetic worker helpers and opt-in live-model runs.

**Other gates.** Run `node scripts/test_convergence.mjs worker` with the pinned OpenCode on PATH (CI checks the archive digest and version). The model is a synthetic loopback server. Run `python3 scripts/test_convergence_mutations.py` to reintroduce thirteen historical faults in temporary copies. A mutant only counts as detected if its adverse case fails for the expected reason and its valid control passes. Run `python3 scripts/validate_storyboards.py` and `python3 scripts/test_storyboard_coverage.py`; the storyboard workflow also runs the browser check with Chrome and its pinned driver.

**Review decision.** Attach same-revision reports, platform results, installed-worker and mutation results to the PR. On provider-facing changes also exercise the opt-in live local-model tests with synthetic data. A newly found defect reopens its family and calls for a new scenario where coverage was missing. A pass on retry needs an explanation. Track faults first found after a green gate and the number of review/repair rounds. Green automation does not accept a method, authorize work, approve a candidate or merge a change.
